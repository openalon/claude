# Claude 专栏写作规范

## 核心原则

- 用自然、具体的中文解释机制，不做逐句翻译。
- 保留 Claude、Claude Code、API、SDK、Agent、tool use 等产品和 API 术语；首次出现时用一句中文说明。
- 官方原意、个人理解、实际验证结果分段写，不把推测写成官方结论。
- 每篇保留可访问的官方 source，不写本机路径，不把私有文件发布到站点。
- 读不到 source 或只能读到片段时停止，不凭记忆补齐。

## 推荐表达

- 先说它解决什么问题，再说它怎么解决，最后说适合谁。
- 用短段落、明确的小标题和可执行的步骤。
- 代码和配置保留原语法；解释用中文，变量名与 API 名不翻译。
- 术语第一次出现时避免堆缩写；图示标签应该能独立读懂。

## 来源与实践

- 「官方内容」只写 source 能支持的内容。
- 「我的理解」用于压缩概念和说明上下文。
- 「实践记录」写实际操作、结果、限制和未验证部分。
- 不整篇复制、翻译或重新包装官方课程；链接回原文。
