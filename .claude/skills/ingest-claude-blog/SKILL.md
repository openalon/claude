# 整理 Claude Blog

用户提供 `https://claude.com/blog` 下的文章，或明确说“整理这篇 Claude Blog”时使用本 skill。单篇 source 写一篇笔记；多个独立来源的比较应先分别落盘，再转为用户明确要求的综合判断。

## 必须遵守

1. 先打开并完整读取官方 source。网页不可访问、需要登录、只有标题、只有摘要或只能读取片段时停止，说明缺失并请求可访问链接或原文；不得凭记忆、标题或搜索摘要补写。
2. 写作前先建立“来源事实表”：记录原文标题、导语、章节顺序、每节核心论点、具体例子、术语、角色分工、限制条件、产品可用性和结论。事实表未完成不得开始成文。
3. 写作时逐项对应事实表：原文明确陈述用“文章指出/原文建议”，个人归纳用“我的理解”，新增建议放入“可尝试的实践”；不能把推断写成官方观点。不要把 `Claude Blog`、Anthropic 或产品名称写成“作出判断”的主体；优先使用“这篇文章讨论/文章提出/原文建议”，并保留“可能、通常、建议”等原文限定语。
4. 必须保留原文的论证链，而不是套用通用目录：说明“问题是什么 → 为什么发生 → 原文提出什么机制 → 如何执行 → 谁负责 → 有哪些限制”。具体例子、数字、流程和条件不得为了简洁全部删掉。
5. 完稿后逐段回读 source 复核。检查每个“官方/文章/原文”表述是否有来源，删除无法核对的断言；若 source 在写作过程中不可访问，停止发布并标注未完成，不得补齐缺口。
6. 写入前检查 source、slug 和目标路径。已有笔记默认不覆盖；需要更新时保留原 `id`，栏目页不重复添加链接。
7. 不整篇翻译或复制原文。保留官方链接、原文标题和发布日期（如果可确认）。不要为了显得完整而虚构引文、数据、示例或产品状态。
8. 明确区分“官方内容”“我的理解”“实践记录”。未实践的内容不得写成已验证；官方产品的 beta、Enterprise、权限和可用性条件必须保留。
9. 标题和 description 必须与实际信息密度匹配；如果文章只是摘要，不得使用“实践手册”“完整指南”等过度承诺的标题。
10. 成品放在 `blog/<slug>.md`，不要放进 `academy/`。

## 笔记骨架

```markdown
---
id: blog_<12 hex>
title: <中文标题>
description: <一句说明>
source: https://claude.com/blog/...
published: YYYY-MM-DD
updated: YYYY-MM-DD
tags:
  - Claude
status: published
---

# <中文标题>

<来源 chip 或官方原文链接>

## 先说结论
## 它解决什么问题
## 关键机制
## 适合谁
## 我的理解
## 实践记录

> 尚未实践的内容写明“待验证”，不要伪造结果。
```

## 完成检查

- source 可打开、完整读取且与内容对应
- 已完成来源事实表，并保留原文论证链、例子和限制条件
- 每个官方断言都能回指 source；没有凭标题、记忆或摘要补写
- id 已存在且更新时保留
- 没有整篇翻译、伪造引用、虚构数据或夸大产品可用性
- 官方内容、个人理解、实践结果边界清楚
- 标题和 description 没有超过正文实际信息密度
- 文章已落盘到 `blog/`
- 栏目索引/导航更新是幂等的
